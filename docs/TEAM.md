# 10시간 해커톤 실행 계획 — 3인 팀

> **해커톤 시작 전에 팀원 3명이 다 같이 이 문서를 끝까지 읽으세요. 15분이면 됩니다.**
> 이 15분이 10시간 중 3시간을 아껴줍니다.

---

## 0. 먼저 — 10시간의 현실

이 레포의 다른 문서(`README.md`, `DATABASE.md`, `DEVELOPMENT_GUIDE.md`)는 **"돈 받고 제대로 만들 때"** 기준으로 쓴 설계서입니다. 10시간 해커톤에서는 그 내용의 **90%를 버립니다.** 버리는 게 실패가 아니라, 안 버리면 확실히 실패합니다.

초보 팀이 해커톤에서 망하는 순서는 거의 항상 똑같습니다.

1. 설계서에 있는 걸 다 만들려고 한다
2. DB 설치와 환경 설정에 3시간을 쓴다
3. 8시간째에 아직 화면이 하나도 안 뜬다
4. 발표 10분 전까지 코딩하다가 **아무것도 못 보여주고 끝난다**

심사위원은 여러분의 코드를 읽지 않습니다. **3분짜리 데모 하나**를 봅니다.
그래서 우리의 목표는 "완성된 서비스"가 아니라 **"작동하는 데모 1개"** 입니다.

### 우리 데모 한 문장

> **"시급 12,000원짜리 알바가, 실제로는 시급 9,276원입니다."**

이 문장을 화면으로 증명하면 이깁니다. 이거 말고는 다 부차적입니다.

| 단독 계산기 (S-04) | ✅ | 🔶 여유 되면 | 검색이 되면 자동으로 따라옴 |

### DB를 버리는 게 왜 옳은가

초보 팀이 가장 자주 하는 실수가 "일단 DB부터 세팅"입니다. 그런데 우리 서비스는:

- 사람인 공고는 **어차피 외부 API에서 실시간으로 가져옵니다** → 저장할 이유가 없음
- 사장님 공고는 **5건이면 데모에 충분합니다** → JSON 파일이면 끝
- 캐시는 **서버가 켜져 있는 동안만 유지되면 됩니다** → JS `Map` 하나

10시간 안에 DB가 주는 이득은 0이고, 비용은 3시간입니다. **DB 안 씁니다.**

## 2. 기술 스택 (해커톤 버전)

```
Next.js 14 (App Router) + TypeScript + Tailwind CSS
└─ 프론트 + 백엔드가 한 프로젝트 안에 같이 있음 (서버 따로 안 띄움)

데이터 저장   → 없음. data/ownerJobs.json + 메모리 Map
배포         → Vercel (GitHub 연결하면 push할 때마다 자동 배포, 10분이면 끝)
```

### 시작하기 — 뼈대는 이미 레포에 있습니다

`create-next-app`을 새로 돌릴 필요 없습니다. **3명 모두 clone 받고 바로 시작하세요.**

```bash
git clone https://github.com/ehrud8657/Realba.git
cd Realba
npm install
npm run dev
```

브라우저에서 `http://localhost:3000` 을 열면 **목데이터 기준으로 홈 → 검색 → 상세가 이미 동작합니다.**
API 키가 하나도 없어도 돌아갑니다. (키를 넣으면 자동으로 진짜 데이터로 바뀝니다)

여기서 화면이 안 뜨면 **다른 작업 하지 말고 이것부터 해결하세요.** 셋 다 dev 서버가 뜨는 걸 확인한 뒤에 흩어집니다.

```bash
cp .env.example .env.local   # 키가 생기면 여기에 채워 넣습니다
```

### 뼈대 코드가 이미 해결해 둔 것

- **외부 API 없이도 전부 동작합니다.** `/api/jobs`가 키 유무를 보고 목데이터와 실데이터를 자동으로 바꿔 씁니다. B와 C는 A를 기다리지 않아도 됩니다
- 검색 결과 화면 우측 상단에 `MOCK` / `LIVE` 배지가 떠서, 지금 어떤 데이터를 보고 있는지 바로 알 수 있습니다
- 상세 화면의 근무시간 슬라이더는 서버에 다시 묻지 않고 `lib/calc.ts`로 그 자리에서 재계산합니다 (그래서 즉시 반응합니다)
- 경로를 못 구한 공고는 계산 없이 목록 맨 뒤로 보내고, 에러를 던지지 않습니다

## 3. 역할 분담

**BE 1명 + FE 2명**을 추천합니다. 10시간에 만들 API는 사실상 **1개**(`/api/jobs`)뿐이고, 화면은 3개라서 프론트에 사람이 더 필요합니다.

### A — 백엔드 / 데이터

| | |
|---|---|
| **한 문장** | 출발지와 키워드를 받아서, 실질시급이 계산된 공고 목록을 돌려주는 API 1개를 만든다 |
| **만드는 것** | `lib/calc.ts`, `lib/saramin.ts`, `lib/geocode.ts`, `lib/odsay.ts`, `api/jobs/route.ts`, `types.ts` |
| **절대 안 하는 것** | 화면, CSS, 컴포넌트, DB, 로그인 |
| **성공 기준** | 브라우저에서 `/api/jobs?...` 를 열었을 때 JSON이 나온다 |
| **가장 큰 리스크** | 외부 API 3개가 생각대로 안 움직임 → **시작 30분 안에 3개 다 호출 테스트부터** |

### B — 프론트엔드 (검색 흐름)

| | |
|---|---|
| **한 문장** | 홈에서 출발지·키워드를 입력하면 결과 리스트가 뜨는, 데모의 뼈대를 만든다 |
| **만드는 것** | `app/page.tsx` (S-01), `app/search/page.tsx` (S-02), `components/JobCard.tsx` |
| **절대 안 하는 것** | API 내부 구현, 계산 로직 |
| **성공 기준** | 홈 → 검색 → 결과 카드 리스트가 **가짜 데이터로** 끝까지 흘러간다 |
| **핵심 원칙** | **A를 절대 기다리지 않는다.** `mockJobs.json`으로 먼저 다 만들고, 나중에 API 주소만 바꿔 끼운다 |

### C — 프론트엔드 (상세) + 데이터 + 발표

| | |
|---|---|
| **한 문장** | 계산 과정을 보여주는 상세 화면을 만들고, 데모 데이터와 발표를 책임진다 |
| **만드는 것** | `app/jobs/[id]/page.tsx` (S-03), `components/CalcBreakdown.tsx`, `data/ownerJobs.json`, `data/mockJobs.json`, **발표자료 + 데모 대본** |
| **절대 안 하는 것** | API, 검색 화면 |
| **성공 기준** | 계산 과정 카드가 화면에 뜬다 + **발표 대본이 완성돼 있다** |
| **왜 발표를 개발자가?** | 해커톤 점수의 절반은 발표입니다. 아무도 안 맡으면 발표 30분 전에 급조하게 되고, 그게 제일 흔한 패배 원인입니다 |

> **C의 역할이 제일 중요합니다.** 초보 팀은 "3명 다 코딩"을 선택하고, 발표 준비를 아무도 안 해서 집니다. C는 H+7부터 코딩을 줄이고 발표에 집중하세요.

### 파일 소유권 — 충돌 방지의 핵심

**같은 파일을 두 사람이 동시에 고치지 마세요.** 초보 팀이 git으로 겪는 사고의 95%가 여기서 나옵니다.

| 파일 | 주인 | 다른 사람은 |
|---|---|---|
| `src/lib/*` | **A** | 읽기만 |
| `src/app/api/*` | **A** | 읽기만 |
| `src/types.ts` | **A** | 읽기만. 바꿔야 하면 **A에게 말로 요청** |
| `src/app/page.tsx`, `src/app/search/page.tsx` | **B** | 손대지 않음 |
| `src/app/jobs/*` | **C** | 손대지 않음 |
| `src/data/*` | **C** | 읽기만 |
| `src/components/*` | B, C 나눠서 | **파일 단위로 나눔.** 한 파일을 둘이 고치지 않음 |
| `package.json` | **A** | 라이브러리 설치가 필요하면 A에게 요청 |

#### 계산 함수 (`src/lib/calc.ts`) — 이대로 쓰세요

```ts
import type { Calc } from '@/types';

export function calcRealWage(params: {
  hourlyWage: number;
  dailyWorkHours: number;
  oneWayMinutes: number;
  oneWayFare: number;
}): Calc {
  const { hourlyWage, dailyWorkHours, oneWayMinutes, oneWayFare } = params;

  // 왕복 기준
  const dailyCommuteCost  = oneWayFare * 2;
  const dailyCommuteHours = (oneWayMinutes * 2) / 60;

  const dailyNetPay        = hourlyWage * dailyWorkHours - dailyCommuteCost;
  const totalOccupiedHours = dailyWorkHours + dailyCommuteHours;
  const realHourlyWage     = Math.round(dailyNetPay / totalOccupiedHours);

  return {
    nominalHourlyWage: hourlyWage,
    realHourlyWage,
    dailyNetPay,
    totalOccupiedHours: Math.round(totalOccupiedHours * 100) / 100,
    lossRate: (hourlyWage - realHourlyWage) / hourlyWage,
  };
}
```

**검산 (이 값이 안 나오면 코드가 틀린 겁니다)**

```
calcRealWage({ hourlyWage: 12000, dailyWorkHours: 5,
               oneWayMinutes: 35, oneWayFare: 1400 })
→ realHourlyWage: 9276, lossRate: 0.227
```

const cache = new Map<string, Route>();

export async function getRoute(o: LatLng, d: LatLng): Promise<Route | null> {
  const key = `${o.lat.toFixed(4)},${o.lng.toFixed(4)}-${d.lat.toFixed(4)},${d.lng.toFixed(4)}`;
  if (cache.has(key)) return cache.get(key)!;

  try {
    const route = await callOdsay(o, d);
    cache.set(key, route);
    return route;
  } catch {
    return null;   // 실패해도 서비스는 계속 돌아야 함
  }
}
